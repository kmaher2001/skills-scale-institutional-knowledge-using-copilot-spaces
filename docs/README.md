# OctoAcme Project Management Docs

## Process overview

OctoAcme uses an iterative project lifecycle: initiation, planning, execution,
release, and retrospective. Initiation establishes the business need, success
metrics, stakeholders, and approval to proceed. Planning turns the initiative
into a prioritized backlog with acceptance criteria, estimates, milestones,
dependencies, and a Definition of Done.

The Project Manager coordinates delivery, schedules, risks, and communications;
the Product Manager defines outcomes, prioritizes work, and measures success.
Developers build and test features, QA validates quality and acceptance
criteria, and stakeholders provide input and approvals.

Teams track work on a project board and use standups, delivery syncs, demos, and
stakeholder updates to share progress and surface blockers. Risks and
dependencies are recorded and reviewed regularly; unresolved issues escalate
from the team through the Project Manager and Product Lead to the sponsor when
necessary.

Quality practices include small pull requests, automated tests and linting,
review approvals, security scanning, and manual QA where needed. Releases require
passing checks, smoke tests, release notes, and a rollback plan. Retrospectives
after sprints, releases, milestones, or incidents turn lessons into owned,
tracked improvements.
